# 橙墨写作规范（writing-guide）

> 供 agent 按橙墨/中登系风格产出公众号 Markdown。产出物是**标准 Markdown + 橙墨扩展语法**，不绑死橙墨——纯标准 Markdown 工具也能打开。

## 1. 标题纪律

```markdown
# 文章标题        ← 全文只用一次
## 二级标题       ← 正文分段的主力
### 三级标题      ← 确需子层级才用
```

- 中登系是**叙事**不是论文：能不用三级就不用，H4 基本不出现
- 渲染效果：H1 22px 深蓝黑 + 橙底线；H2 19px + 橙左条；H3 17px 深橙；H4 16px 暖棕

## 2. 结构化模块（橙墨扩展 `:::` 语法）

用模块**组织观点结构**，而不是手调样式。四个模块：

| 模块 | 何时用 | 频率纪律 |
|------|--------|----------|
| `:::intro` | 栏目开场：期次 + 标题 + 一句副题 + 元信息 | 每篇最多 1 个，放文首 |
| `:::quote` | 用一个**判断句**收住一段论述 | 1~2 个/篇，宁缺勿滥 |
| `:::steps[标题]` | 可操作的清单（每行 `标题 \| 说明`，说明可省） | 内容真的是步骤才用 |
| `:::point` | 全篇核心判断（深底观点卡） | **每篇最多 1 个** |

```markdown
:::intro
eyebrow: 中登行走中 · 第 07 期
title: AI 味是什么
subtitle: 先看看里面有没有人，再谈要不要去那股味。
meta: 2026.09.15 · 登叔
:::

:::quote
text: 别急着"去 AI 味"，先看看里面有没有人。
from: 中登行走中 · 第 07 期
:::

:::steps[三步判断一段文字里有没有人]
找一个具体的细节 | 看他写的是"天气很好"还是"风把纸吹跑了"
试着把它换掉 | 换成谁写都成立的句子，通常就没有人了
:::

:::point
eyebrow: 本期观点
text: 去 AI 味不是去掉机器感，是补上一个人。
note: 补充说明（可删本行）
:::
```

未识别的 `:::xxx` 会**原样保留**不吞内容——写错指令名不会丢稿，但渲染不对，发布前看自检报告。

## 3. GFM 警告块（中文徽章自动生成）

```markdown
> [!NOTE]      → 「说明」徽章（蓝系）——补充说明、关键洞察
> [!TIP]       → 「提示」徽章（棕系）——技巧、建议
> [!IMPORTANT] → 「重点」徽章（橙系）——核心观点、关键结论
> [!WARNING]   → 「注意」徽章（琥珀）——风险提示、对比反差
> [!CAUTION]   → 「警告」徽章（红系）——严重警告，少用
```

引用块内**每一行独立显示**（橙墨会把引用块内换行渲染为分行），适合逐条列举。

## 4. 强调与细节

- **加粗**：核心概念、关键数字、重要结论——渲染为红橙色，是「中登金句」的主要载体；不要整段加粗
- *斜体*：少用（灰色的次级信息）；**图片后紧跟的斜体行会自动变成居中题注**（这是题注的正确写法）
- `行内代码`：技术名词（`Spring Boot`、`Cursor`）
- 中英文之间的空格**不用手打**，渲染器自动加
- 脚注：正文 `[^id]` 引用 + 文末 `[^id]: 出处说明` 定义行（公众号不支持锚点跳转，渲染为上标编号 + 文末「参考」块）；微信不支持外链，**引用来源一律走脚注**（如 `[^k1]: 中华网 2026-07-06 报道《…》`）

## 5. 结构与语气（中登系）

- 叙事优先：能用段落讲清的不用列表；列表用 `-`，加粗起头
- 分割线 `---` 当「呼吸停顿」用，前后空行
- 结论前置，姿态平视：不贩卖焦虑、不爹味说教
- 首段（H1 后第一段）自动渲染为略大的导语——把它写成「一段话讲清这篇为什么值得读」

## 6. 发布前自检清单

1. `# 标题` 只出现一次；`:::point` ≤1；`:::intro` ≤1
2. 外链没有裸写 `<a>` 或裸 URL（走脚注）
3. 表格 ≤4 列
4. 跑 render.mjs，自检 0 项、退出码 0
5. 图片：API 发布路径需先传素材库（见 SKILL.md 图片章节）
