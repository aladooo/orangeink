# 微信兼容踩坑手册（docs/wechat-compat.md）

公众号的解析行为是黑盒且会变。这份手册收录橙墨在**真实发布流程中实测踩到**的坑与修法——每一条都付过「线上弹窗 / 版面塌掉」的学费。报兼容性坑请对照这里的格式（可复现最小 HTML + 现象 + 修法）。

## 坑 1｜段内含加粗 → 被误判「行高叠字」

- **现象**：正文一段只要带 `**加粗**`，粘贴进公众号就弹「行高小于字体大小，多行文字可能重叠」。
- **根因**：官方布局检测用 `getClientRects()` 的矩形数估行数。段落里有带内联样式的子元素（如 `<strong>`）时，一段文字被拆成多个矩形，被当成了多行。
- **修法**：渲染管线最后一步 `polish()` 里做 `wrapTextRuns`——**所有直接文本节点都包一层 `<span leaf>`**，让块容器内不再有「带样式的兄弟结构」，矩形数恢复 1 段 1 矩形。
- **护栏**：自检器里那条「1.3 行高叠字（官方实测口径）」就是回归测试——正常恒为 0 项，`wrapTextRuns` 被误删它立刻亮。

## 坑 2｜一键复制后报「结构异常」（双根因）

- **现象**：复制粘贴后公众号弹「检测到结构异常代码」。
- **根因 A**：`execCommand('copy')` 走选区复制，会把浏览器附加的 UA 属性、多余样式一起带进剪贴板。
- **根因 B**：剪贴板 HTML 未净化，残留危险样式。
- **修法**：弃用 `execCommand`，在 **`copy` 事件里用 `clipboardData.setData('text/html', …)` 自建 HTML**，且生成前先净化——去掉 UA 附加属性、过滤危险样式、行高统一折算 px。

## 坑 3｜分割线粘贴后消失

- **根因**：微信解析会剥空标签。
- **修法**：分割线是 36×4px 橙条，**条内塞 `&nbsp;`** 保住标签基线。

## 坑 4｜引用块多行被合并

- **根因**：连续 `>` 行渲染成一个块，微信里折行丢失。
- **修法**：引用块内**按行渲染 `<br>`**（嵌套按深度计数），即 `quote_breaks` 策略。

## 坑 5｜提示块「下松上紧」

- **现象**：GFM 提示块（`> [!NOTE]` 等）与后续内容的间距异常。
- **修法**：`polish()` 对引用/警告类块（特征 `border-radius:0 6px 6px 0`）**清零末子元素的 margin-bottom**，统一由容器控制留白。

## 坑 6｜无单位行高 → 线上误报「行高小于字号」

- **根因**：线上旧口径 = 元素高度 ÷ `parseFloat(line-height)`。写 `line-height:1.8` 时 `1.8` 被当 1.8px，估出几十行、平均行高 1.8 < 字号 → 误报（doocs 默认样式踩的同一坑）。
- **修法**：**行高一律输出 px**（`lh(字号, 倍率)`），且带 px 行高的元素必须同时有显式 `font-size`，否则行高与字号在不同端错配。

## 坑 7｜font-family 白名单

- **规则**：官方只放行 `"mp-quote", PingFang SC, system-ui, -apple-system` 这一条链，其余一律判违规（含复制时泄漏的系统字体栈）。
- **推论**：**正文不写 font-family**。想要「标题宋体」没有合规实现——读者设备不会因此加载宋体，栏目辨识度只能靠字重 / 字号阶梯 / 字距 / 配色秩序承担。
- **橙墨做法**：正文不写 font-family；黑体（标识）×宋体（节目标题）的对比改在封面图里做。

## 坑 8｜`**` 紧贴中文标点 → 加粗失效

- **根因**：CommonMark 分隔符「左右翼」规则——开 `**` 右侧紧跟标点时，左侧必须是空白/标点才开得了；闭 `**` 左侧紧跟标点时，右侧必须是空白/标点才收得了；`**` 内侧带空格直接失效。中文写作高频踩雷。
- **修法**：① 把标点移到 `**` 外（首选，如 `"**五天玩转大理丽江**的通用攻略"`）；② `**` 前加空格；③ 整句独立成行（行首/行尾不受限）。
- **护栏**：自检器「加粗/斜体未生效」直接抓渲染后残留的裸星号（v1.0.1 起）。

## 坑 9｜同标签嵌套过深 → 节点被静默删除

- **规则**：同标签 + 同样式的单子链连续嵌套超过 15 层（2026-09 口径），公众号自动删节点，版面塌陷且无提示。
- **橙墨做法**：自检器按同规则扫描，超限按违规报。

## 附｜发布四条硬约束（橙墨输出已内置）

1. 行高**一律 px**，绝不输出无单位数字；
2. 正文**不写 font-family**（白名单外全违规）；
3. 复制必须在 **`copy` 事件里 `clipboardData.setData`** 自建 HTML，且先净化；
4. **所有直接文本节点包 `<span leaf>`**（防矩形计数误判，见坑 1）。

> 这些规则微信随时可能调整。发现新坑请开 issue，附**可复现的最小 HTML 片段**（复制出来的 payload 更好）——每个实弹坑都会更新进本手册。
