海棠 × 黛蓝　—— 「纸上行舟小说集」专用主题（key: haitang）

为《九千九百九十九张》在公众号「纸上行舟小说集」连载设计。配色承接视频端「纸上行舟」已定稿的品牌基因：黛蓝 #274770 · 卡其 #a58650 · 海棠纸意。

除配色外，本主题新增 4 条结构渲染规则（刊头 / 章节牌 / 结尾帧卡 / 落款），把 Lilith 文稿的固定规格行（# N-00X-上、> 引子：、> 结尾帧：、第X章　Y、——千槿）自动转成统一版式——文稿一字不改，粘贴即排。

我醒来的时候，第一个念头，是：这是哪儿。可这个念头很轻，落不到实处——像一片叶子落在水上，浮着，不沉。

屋里很小。石头铺地，缝里长着薄薄一层青苔，踩上去是凉的。

纸上写着字。一行一样，写了三遍——

苍滟喜欢千槿。

苍滟。念着这两个字，舌尖是熟的，心口是空的。像在念别人的名字。

药是黑的，苦味压过了海棠。我端起来，喝了一口，舌根发麻。

③ 文稿写法 → 渲染对照（文稿一字不改）

Lilith 文稿原文（已是这样，不用改）渲染结果
# N-001-上刊头顶行：行章 + 刊名 + 细线 + 「第 001 集 · 上」；书名行「九千九百九十九张 · 001」（卡其方块前缀）
> 引子：她每天醒来，都不记得爱过谁刊头引子行（并入刊头，居中灰字）
第一章　醒 或 **第四章　规矩**（独立短行）章节牌（A/B 案二选一，全稿统一）
——千槿（独立短行）右对齐落款（灰卡其小字）
---卡其金短条分割线（36×4，自动随主题）
> 结尾帧：原句「…」＋下集预告「…」结尾帧卡：原句大字（胭脂）+ 卡其细条 + 下集预告行

识别规则都带形态约束（如章节行 ≤20 字且匹配「第X章」、落款 ≤8 字且以「——」开头），普通文章不受影响；系列名「纸上行舟小说集」与书名《九千九百九十九张》为主题常量，换书时改一处。

⑤ 多书范式（总账号「纸上行舟小说集」· 每书一主题）

「纸上行舟小说集」是总账号，后续会有多部小说连载。设计上把「变」与「不变」分开——范式不变，每书一注册：

层内容变化频率
范式层（共享代码）4 条结构规则：刊头 / 章节牌 / 结尾帧卡 / 落款+刊尾——版式骨架、识别逻辑、AA 校验全部只写一次基本不变
注册层（每书一份）主题注册项 = novel 元数据（书名、刊名、集数格式）+ 色板（可整书换色系）+ alerts每部小说一份（~25 行）
文稿层（Lilith）规格行照旧（# N-00X-上 / > 引子： / 章节行 / > 结尾帧：）——任何书同构不变
本期注册项示例（九千九百九十九张 → haitang 海棠×黛蓝）：
novel: { 书名:'九千九百九十九张', 刊名:'纸上行舟小说集', 集数:'第 001 集 · 上', 刊尾:'刊—001·上' }
未来新书（示意）：只需新增一个注册项——比如换一套「青瓷 × 玄墨」色板 + 新书名，范式代码零改动，主题下拉自动出现。

⑥ 设计决定（2026-10-14 已确认 ✅）

  1. 章题来源：从集内首个章节行自动提取（如 N-001-上 正文中的「第一章　醒」→ 刊头大字「醒 · 上」）——文稿零改动（比原 A 案更优，正文里本来就有章题）
  2. 刊头刊名：「纸上行舟小说集」（红「行」方章 + 深蓝刊名）
  3. 章节牌：A 案细线夹注（两侧卡其细线 + 深蓝字）
  4. 加粗强调色：海棠胭脂 #9e3b33（默认案）
  5. 结尾卡底色：海棠纸底（主案）
  6. 刊尾行：保留「纸上行舟小说集 · 刊—001·上」细线行（默认案）

④ 实现方案（确认设计后编码）

  1. 范式层（共享，一次写死）：4 条结构规则——刊头（H1+引子行）/ 章节牌 / 落款 / 结尾帧卡+刊尾，core rule 解析 + renderer，浏览器版与 CLI 同口径；只命中小说稿形态，普通文章不受影响
  2. 注册层（每书一份）：haitang 主题注册项 = novel 元数据（书名/刊名/集数格式）+ 色板 + alerts（~25 行），主题下拉自动出现；未来新书只加注册项
  3. 同步面：template.html → build.py 重建 → render.mjs（CLI 同口径）→ parity-check 对拍 → 本机 skill 副本 → 发版（预计 v1.3.0，含 minor 语义）
  4. 验收：N-001-上 真实稿整篇渲染 + 对拍逐字节一致 + 自检 0 项 + AA 全过 + 主题下拉可见「海棠 × 黛蓝」
